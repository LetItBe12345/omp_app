## 第一批确认决策

1. Runtime 环境与网络都在 Electron Main 启动 OMP 时解析，通过 `spawn` 的 `env` 注入；不通过 RPC 热更新。
2. 修改最终环境或网络后必须重启 OMP Runtime，并恢复当前 Session；Workspace 切换沿用既有重启流程。
3. MVP 不实现独立 Settings 页面。网络控件放在输入框顶部，与模型、推理强度和权限控件同级。
4. 代理控件的一级菜单提供“关闭”“自动”和“手动”；点击“手动”后，在同一 Popover 内切换到带返回入口的二级配置面板，不嵌套第二个浮层。
5. Runtime Network 配置按当前机器全局保存，切换 Workspace 后继续使用同一模式和手动代理端口。
6. 首次启动默认使用“自动”模式。它重新探测 Login Shell；检测到受支持代理时注入，未检测到时不注入并正常启动。
7. VPN 状态变化后不做后台轮询。用户通过网络菜单重新检测；重新检测导致最终环境变化时重启 Runtime。
8. 手动代理不设置默认端口，也不扫描常见端口。用户只填写本地 HTTP 代理端口，应用生成 `http://127.0.0.1:<端口>`。
9. MVP 手动代理只支持本机、无认证的 HTTP 代理端点；暂不引入代理凭据存储。
10. Agent 正在生成或存在 Follow-up 时禁用网络控件。执行链空闲后才能修改，避免重启导致当前任务和队列丢失。

## 第二批确认决策

11. Provider 登录中的授权网页继续通过系统默认浏览器打开，不受 Runtime Network 配置控制。OMP 内部授权 API 和模型请求使用 Runtime 代理。
12. 手动代理面板中的测试只检测 `127.0.0.1:<端口>` 是否可连接，文案明确为“检测端口”，不声称已验证外网、Provider 或模型。
13. 手动代理面板不显示 Bypass / NO_PROXY。应用始终自动追加 `localhost`、`127.0.0.1` 和 `::1`，避免本地服务经过代理。
14. 自动模式只读取新 Login Shell 中的代理变量，不读取 GNOME、KDE、PAC 或其他系统代理配置。
15. 自动模式只检测到 SOCKS4/SOCKS5 代理时不注入代理，也不阻止 Runtime 启动；界面提示改用 VPN 的本地 HTTP 入站。
16. 网络一级菜单底部提供“环境诊断”入口，打开只读 Dialog；不增加独立环境控件或 Settings 页面。
17. 网络模式和手动端口先形成未应用草稿，用户点击“应用并重启”后才保存并重启 Runtime；不再弹第二个确认对话框。
18. 手动代理 Host 固定为本机回环地址，不支持局域网或公网代理服务器；端口允许 `1–65535`。
19. 手动面板只显示本地 HTTP 代理端口输入框、检测端口和应用操作，不显示协议、Host、完整 URL、认证或 Bypass。
20. 工具栏按钮使用“代理：关闭 / 自动 / 手动”，只显示当前模式，不显示端口。解析来源、实际结果和错误在一级菜单内展示。

## 第三批确认决策

21. 环境诊断和复制结果只包含白名单摘要：Shell、PATH、Workspace、内置 OMP 路径与版本、开发工具路径与版本、网络模式和脱敏代理来源；不枚举完整环境变量。
22. 应用新网络配置后如果 Runtime 启动失败，保留新配置并显示错误，不自动回退到上一个配置或直连。
23. 手动代理端口检测是可选操作。只要端口格式和范围合法就允许应用，用户可以先保存配置再启动 VPN。
24. “关闭”仅表示不向 Runtime 注入显式代理变量，不承诺绕过 TUN 或系统路由；该说明放在一级菜单中。
25. 自动模式允许把 Login Shell 中带用户名和密码的 HTTP 代理临时传给 Runtime，但凭据不持久化、不显示，所有日志和诊断必须完全脱敏。
26. Provider 登录进行期间禁用代理控件，登录完成或取消后才能修改，避免重启取消授权流程。
27. Runtime 处于 `failed` 或 `stopped` 时仍允许修改代理；应用后尝试启动或重启 Runtime，作为网络错误恢复入口。
28. 没有活动 Workspace 时也允许保存全局代理配置，下次启动 Runtime 时应用；此时操作文案为“保存”，不执行重启。
29. 关闭代理 Popover 时丢弃所有未应用草稿，下次打开恢复当前已保存配置，不增加放弃确认。
30. 从手动模式切换到自动或关闭后，继续全局保留上次手动端口；再次切回手动时自动带出。

## Environment Profile 范围

- MVP 不提供 Shell、PATH、自定义环境变量或 Workspace 覆盖的编辑 UI。
- Main 自动探测用户 Login Shell 并读取完整环境；探测失败时退回 Electron 启动环境，同时提供明确诊断。
- 网络规则在普通环境解析之后应用，因此“不注入代理”必须删除 Login Shell 或 Electron 环境带入的代理变量。
- 环境检测提供只读结果，不建立完整 Environment Profile 编辑器。

## 已确认的范围调整

- SOCKS5 不属于 MVP 的全 Runtime 代理能力。当前 OMP/Bun 的 Provider fetch 不能仅靠 SOCKS5 环境变量获得完整支持。
- 代理认证、Workspace 级 Environment 覆盖和完整 Environment Profile 编辑留待出现明确需求后另建任务。
- “不注入代理”只保证删除显式代理变量，不能绕过由操作系统路由层接管的 TUN/VPN。

## 实施分段

1. 增加 Main 环境解析模块，异步探测 Login Shell、解析 NUL 分隔环境并生成白名单诊断。
2. 增加纯网络解析逻辑，负责配置校验、代理变量清除与生成、固定回环绕过和本地端口检测。
3. 在现有 `desktop-state.json` 的全局 UI 状态中保存代理模式和手动端口，不升级状态版本。
4. 让应用恢复、Workspace 激活、手动重启和网络应用路径统一传入解析后的最终环境。
5. 扩展 Runtime 重启入口，使其接受新环境并沿用当前 Session 恢复流程。
6. 通过 Shared API、Preload 和 Main IPC 暴露读取代理状态、应用配置、检测端口和读取诊断的专用方法。
7. 在现有输入框控制栏中增加独立代理控件，实现一级模式菜单、手动二级面板和诊断 Dialog。
8. 依次完成环境与网络纯函数测试、状态与 IPC 测试、Renderer 交互测试、假 Runtime 继承测试和真实 VPN 验收。
